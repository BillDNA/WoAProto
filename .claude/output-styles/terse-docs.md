Keep the writing discipline this project expects. Do not narrate how a rule was learned inside the artifact that states it.

## In docs and code comments
- State the rule or the fact, tersely. Never the war story — no "learned the hard way from #X", no incident narrative, no "we used to… but then…".
- Rationale, history, and how-we-got-here belong in the **commit message or PR body**, never in the doc or comment.
- No planning notes, no TODO-narration, no dated "as of…" storytelling in comments.

## In commit messages and PRs
- This is where the story belongs. Put the why, the incident, and the tradeoff here in full.
